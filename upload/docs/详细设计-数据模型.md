# 详细设计-数据模型

更新时间：2026-04-22

## 1. 数据模型总览

核心表（Prisma）：

- `users`
- `batches`
- `farming_logs`
- `disease_records`
- `risk_records`
- `products`
- `trace_records`
- `fruit_grade_records`
- `weather_cache`

## 2. 主要关系

- `users (1) -> (N) batches`
- `batches (1) -> (N) farming_logs`
- `batches (1) -> (N) disease_records`
- `batches (1) -> (N) risk_records`
- `batches (1) -> (N) products`
- `products (1) -> (N) trace_records`
- `batches (1) -> (N) fruit_grade_records`

## 3. 关键业务字段

### 3.1 disease_records

- `disease_name`
- `confidence`
- `severity`（`low/mid/high`）
- `status`（`normal/review`）
- `raw_result`（模型细节）

### 3.2 risk_records

- `risk_level`（`low/mid/high`）
- `level_text`
- `summary`
- `suggestion`
- `source_data`

### 3.3 fruit_grade_records

- 输入特征：`diameter,brix,weight,defect_level`
- 感知结果：`color_score,defect_ratio,size_score,maturity_score`
- 决策结果：`grade_code,grade_text,retail_* ,wholesale_*`
- 可追踪：`request_id,engine_source,decision_source,model_version`

### 3.4 trace_records

- 快照字段：`batch_snapshot,logs_snapshot,inspections_snapshot`
- 校验字段：`proof_type,proof_hash,chain_hash,verified,verified_at`
- 锚定字段：`anchor_status,tx_id,block_number,chain_provider,chain_network,anchored_at`

## 4. 枚举与状态口径

- `RiskLevel`: `low/mid/high`
- `DiseaseSeverity`: `low/mid/high`
- `DiseaseStatus`: `normal/review`
- `ProductStatus`: `pending/listed`

## 5. 数据一致性原则

1. 主键与唯一键严格由后端维护。  
2. 兼容字段仅在接口层保留，不进入核心存储语义分叉。  
3. 关键流程结果必须可落库（便于审计与回放）。

## 6. 演进建议

- 为 `logout` 与 token 生命周期补专用表或黑名单。  
- 为 AI 调用观测补 `ai_inference_logs`（若后续需要精细观测）。  
- 风险真实闭环可新增 outcome 事件表。

# 详细设计-前端小程序

更新时间：2026-04-22

## 1. 前端结构

- 页面：`pages/*`
- 服务层：`services/*`
- 组件：`components/*`

## 2. 页面列表（当前）

- `home`
- `login`
- `mine`
- `batch-list`
- `batch-detail`
- `batch-create`
- `farming-log`
- `farming-log-create`
- `disease-recognize`
- `risk-warning`
- `fruit-grade`
- `product-qrcode`
- `trace-view`

## 3. 服务层职责

- `request.js`
  - 统一请求封装、自动注入 token、统一错误处理
  - 支持 `tryReal(real, mock)` 回退策略
- `config.js`
  - 环境切换（dev/test/prod）
  - mock 策略开关
- 业务服务文件
  - `auth.js`、`batch.js`、`log.js`、`disease.js`、`price.js`、`risk.js`、`product.js`、`trace.js`、`weather.js`

## 4. 前端关键实现点

1. 兼容参数映射
- 例如 `batch_id -> batchId`
- `packaging -> packageType`

2. 兼容字段映射
- 病害接口将后端字段映射为 `label/advice` 等页面友好字段

3. 失败降级
- `MOCK_FALLBACK` 打开时，真实请求失败可回退 mock

4. 上传流程
- 病害识别与果实分级支持 `wx.uploadFile`

## 5. 前端已知风险

- 生产环境若保留 `MOCK_FALLBACK=true`，可能掩盖真实后端问题。
- 一些页面仍依赖 mock 兜底体验，不适合作为生产成功标准。

## 6. 前端联调建议

1. 开发期：允许 fallback，加速页面联调。  
2. 测试验收期：关闭 fallback，做真实链路验收。  
3. 上线前：严格核验关键页面字段与错误提示路径。

# 病虫害识别对农事日志辅助作用（小程序版）

更新时间：2026-04-23  
适用范围：橘源通微信小程序（`pages/disease-recognize`）+ 后端日志模块（`/api/logs`）+ 病害识别模块（`/ai/disease/predict`）

## 1. 文档目的

本文用于说明：在当前项目实现下，病虫害识别功能如何实质性提升农事日志的记录质量、处置效率和复盘价值，并给出可执行的记录规范与作业建议。

核心结论：病虫害识别不是“替代农技判断”，而是“把巡园发现数字化、结构化、可追踪化”，从而让农事日志从“事后描述”升级为“可驱动决策的过程数据”。

## 2. 当前实现基线（事实口径）

## 2.1 病害识别输入输出

- 识别入口：`POST /ai/disease/predict`（兼容 `POST /api/disease/predict`）。
- 输入方式：图片上传（`file`）或 `imageUrl`，支持 `batchId/batch_id`。
- 稳定关键输出字段：
  - `label`
  - `confidence`
  - `severity`
  - `advice`
  - `needManualReview`

说明：识别结果还会包含 `imageUrl/image_url` 等兼容字段，便于日志落图和前端展示。

## 2.2 农事日志输入能力

- 日志接口：`POST /api/logs`。
- 兼容字段：
  - 批次：`batchId` 或 `batch_id`
  - 类型：`type` 或 `log_type`
  - 内容：`content` 或 `description`
  - 图片：`images` 或 `image_url`
  - 来源：`source`（如 `disease_recognize`、`manual`）

## 2.3 小程序页面侧联动方式

当前页面流程（`pages/disease-recognize/index.js`）为：

1. 用户拍照/选图并发起识别。  
2. 页面展示 `label/confidence/severity/advice`。  
3. 用户点击“保存为农事日志”，小程序调用 `logService.create(...)` 写入日志。  
4. 写入时会带上：
   - `type: '识别'`
   - `description`（由识别结论拼接）
   - `image_url`（服务端图片地址）
   - `source: 'disease_recognize'`

这意味着：日志“是否落库”由用户确认动作控制，符合现场先看结果再入档的实际操作习惯。

## 3. 病虫害识别对农事日志的辅助价值

## 3.1 把“口述巡园”转为“结构化记录”

传统巡园日志常见问题：

- 描述主观：同一症状不同人记录差异大。
- 粒度不一致：有时只写“有病斑”，缺乏可比性。
- 追溯困难：后续复盘很难还原当时严重度和处理依据。

识别能力接入后，日志天然带有统一字段（`label/confidence/severity/advice`），记录维度更标准，可横向比较不同批次与时间段。

## 3.2 提升“发现-记录-处置”闭环速度

病虫害识别结果可直接转为日志内容，减少二次手工整理：

- 现场识别后即可入日志，缩短从发现到登记的时间。
- `needManualReview` 可作为人工复核触发标记，避免遗漏高风险样本。
- `advice` 提供首轮处置建议，帮助班组先执行低风险动作（巡查、隔离、复拍）再升级处理。

## 3.3 提升日志的“可执行性”

当日志只有“发现病害”时，执行层常缺少动作优先级。  
加入识别输出后，可形成可执行信息：

- 可能病害类别（`label`）：确定排查方向。
- 置信度（`confidence`）：判断结论稳定性。
- 严重度（`severity`）：安排处置先后顺序。
- 复核需求（`needManualReview`）：决定是否立即上报农技人员。

## 3.4 为风险预警与复盘提供连续证据

农事日志中持续沉淀的识别事件，能够支持：

- 同批次多次异常的趋势识别（是否持续恶化）。
- “识别结论 -> 用药/修剪/隔离 -> 复查结果”的时序复盘。
- 质量与合规场景下的过程留痕（谁在何时做了何判断与操作）。

## 4. 识别结果到日志的字段映射建议

以下为建议口径，兼容当前代码实现，便于团队统一：

| 识别字段 | 日志承载位置 | 建议写法 | 作用 |
|---|---|---|---|
| `label` | `content/description` | `疑似：{label}` | 明确症状类别 |
| `confidence` | `content/description` | `置信度：{xx.x%}` | 标识不确定性 |
| `severity` | `content/description` | `风险级别：low/mid/high` | 排序处置优先级 |
| `advice` | `content/description` | 逐句落地建议 | 直接指导作业 |
| `needManualReview` | `content/description` + `detail.source` | `需人工复核：是/否` | 决定是否升级处理 |
| `imageUrl/image_url` | `image_url` 或 `images[]` | 存储服务端可访问地址 | 保留现场证据 |
| 记录来源 | `source` | `disease_recognize` | 区分自动辅助与手填日志 |

建议日志模板（与现有页面逻辑一致）：

```text
{label}（置信度 {confidencePercent}，{severity} 级）
{advice}
```

## 5. 标准作业流程（SOP，建议执行）

## 5.1 现场记录流程

1. 进入病虫害识别页面，选择关联批次。  
2. 拍照并发起识别，获得 `label/confidence/severity/advice/needManualReview`。  
3. 班组长或操作员判断结果是否可入档。  
4. 点击“保存为农事日志”，写入 `source=disease_recognize`。  
5. 如需处理，补充后续日志（如喷药、修剪、复查）并关联同批次。

## 5.2 人工复核触发建议

满足任一条件建议立即复核：

- `needManualReview = true`
- `severity = high`
- 关键地块在短时间内重复出现同类异常

复核后建议新增一条人工日志（`source=manual`），记录：

- 人工判断结论
- 采取措施（隔离/清园/喷药/复拍）
- 复查时间点

## 5.3 闭环管理建议

为形成可复盘闭环，建议每次识别异常后至少补齐两类日志：

1. 处置日志：记录具体动作和执行人。  
2. 复查日志：记录处置后结果及是否恢复正常。

## 6. 典型业务场景

## 场景 A：早期异常筛查

- 巡园识别到 `label=anthracnose`、`severity=mid`。  
- 当班即保存识别日志并安排 48 小时内复拍。  
- 价值：防止“发现了但没记”或“记了但忘了复查”。

## 场景 B：高风险快速升级

- 识别 `severity=high` 且 `needManualReview=true`。  
- 日志即时入档并触发人工复核与分区处置。  
- 价值：把高风险样本从普通巡检中“抬升优先级”。

## 场景 C：投入产出复盘

- 批次在 7 天内出现多条“识别->喷药->复查”记录。  
- 管理者可比较不同策略后的恢复效果。  
- 价值：日志从“备案”升级为“经验沉淀与策略优化数据”。

## 7. 对管理层的直接收益

## 7.1 质量收益

- 提升日志客观性：从描述性语言转为字段化信息。
- 降低漏记概率：识别后可一键入日志。
- 强化证据完整性：图像+时间+批次+建议同轨留存。

## 7.2 运营收益

- 缩短异常响应路径：识别结果直接驱动日志和处置。
- 降低沟通成本：班组、农技、管理人员共享同一事实底稿。
- 提升培训效率：新人可按标准字段理解“该看什么、该记什么”。

## 7.3 风控与追溯收益

- 形成连续时序证据，支撑风险预警与溯源说明。
- 可回看同批次历史识别轨迹，辅助判断是否系统性问题。

## 8. 使用边界与注意事项

1. 病虫害识别结论属于辅助判断，不替代人工农技诊断。  
2. 低置信度或高风险样本必须走人工复核，不应直接下最终诊断。  
3. 建议类文案应保守执行，避免把解释文本当作确定性诊疗结论。  
4. 日志应优先记录“做了什么、何时做、结果如何”，避免只记录模型标签。  
5. 图片质量会直接影响识别效果，需规范拍摄（清晰、近景、光照稳定）。

## 9. 可量化评估指标（建议纳入周报）

可从日志与识别记录中持续统计以下指标：

- 识别日志转化率：识别次数中成功保存为日志的比例。  
- 复核触发率：`needManualReview=true` 的占比。  
- 复核完成时效：触发复核到完成人工确认的平均时长。  
- 处置闭环率：异常识别后 72 小时内是否有处置+复查日志。  
- 异常重复率：同批次同类异常在 7 天内重复出现比例。  

这些指标可直接反映病虫害识别对农事管理执行力的实际贡献。

## 10. 结语

在当前 MVP 架构下，病虫害识别对农事日志的最大价值是“让每一次巡园发现都可沉淀、可追溯、可复盘”。  
它把日志从静态台账变成了动态管理工具，为后续风险预警、投入优化和质量溯源提供了高质量过程数据基础。

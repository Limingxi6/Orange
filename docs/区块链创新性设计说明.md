# 橘源通小程序区块链创新性设计说明

更新时间：2026-04-22

## 1. 文档目的

本文聚焦“橘源通”微信小程序在溯源场景中使用区块链的创新性设计，强调两点：

1. 仅基于仓库当前已实现能力总结，不臆造未上线能力。
2. 解释“为什么这样设计”与“相比常见方案创新在哪里”。

## 2. 当前区块链能力范围（事实基线）

当前区块链能力集中在 `trace` 溯源链路，不介入病害分类、果实分级、风险打级等核心确定性计算。

- 核心接口：`GET /api/trace/:code`、`GET /api/trace/:code/verify`
- 主判定逻辑：本地快照重算 `hash` 后做一致性校验（`verified` 由本地哈希结果决定）
- 链上能力定位：EVM 锚定为可选增强，返回 `txId`、`anchorStatus`、`chainNetwork` 等证明字段
- 链上写入内容：仅 `traceCode + proofHash` 最小元数据

这意味着项目采用的是“业务主流程链下确定性 + 链上证据增强”的架构，而非“全部业务链上执行”。

## 3. 创新性一：双轨可信架构（业务可靠性与链上可信并存）

项目没有把“链上成功”当成业务成功的前提，而是拆成两条轨道：

- 轨道 A（主轨）：本地哈希校验，保证系统在离线、网络抖动、RPC 异常时仍能稳定输出结果。
- 轨道 B（增强轨）：链上锚定，提供跨系统可验证的外部证据（`txId`、区块高度、网络信息）。

创新点在于：把“可信”与“可用”同时做到了工程闭环，避免了传统区块链方案里“链上不可用即主流程中断”的问题。

## 4. 创新性二：轻量上链策略（最小必要数据锚定）

常见误区是把完整业务快照、图片甚至日志原文上链，导致成本高、隐私风险高、迭代慢。
本项目采用“最小必要上链”策略：

- 链下保存完整快照（批次、农事日志、病害记录）
- 链上仅保存快照摘要（`proofHash`）与追溯键（`traceCode`）

创新价值：

- 显著降低 Gas 成本与链上存储负担
- 降低隐私泄露和合规风险
- 保持证据可验证性：链下重算 hash 可与链上摘要比对

## 5. 创新性三：可插拔锚定提供方（Hash / Notary / EVM 策略化）

`trace` 模块将锚定能力抽象为 Provider，并通过配置切换：

- `hash`：本地模式（默认）
- `notary`：第三方公证服务模式
- `evm`：链上锚定模式

这使系统具备“同一业务接口，不同可信基础设施后端”的能力。对企业而言，创新点不是“上了某条链”，而是“可信基础设施可替换、可迁移、可灰度发布”。

## 6. 创新性四：MVP 友好的非阻塞锚定机制

在 `trace` 生成/校验流程中，锚定失败不会把主流程判定成失败：

- 锚定失败：更新 `anchorStatus=failed`
- 主流程继续：`verified` 仍由本地哈希结果决定

这是典型的高可用设计：把“强一致业务结果”与“外部增强能力”解耦，避免单点依赖外部链节点或第三方 RPC。

## 7. 创新性五：前端信任可视化设计（不仅是技术实现）

小程序溯源页并非只显示“已上链/未上链”标签，而是给出结构化可信信息：

- 哈希摘要（`proofHash`）
- 交易哈希（`txId`）
- 链网络（`chainNetwork`）
- 锚定时间（`anchoredAt`）
- 重新校验入口（用户可主动触发验证）

创新点在于“把技术证据转化为用户可理解的信任界面”，使区块链价值从后端能力转化为消费端可感知体验。

## 8. 创新性六：合约与部署产物可审计化

项目不仅有合约源码，还把部署产物与后端配置片段标准化：

- 合约源码：`TraceAnchor.sol`
- ABI：`TraceAnchor.json`
- 部署记录：`deployments/sepolia.json`
- 后端环境片段：`deployments/sepolia.backend.env`

这形成了“开发-部署-联调-审计”闭环，减少“口头上链、证据缺失”的交付风险。

## 9. 与常见区块链溯源方案对比

| 对比维度 | 常见方案（全量上链倾向） | 橘源通当前方案 |
| --- | --- | --- |
| 业务判定 | 依赖链上状态 | 依赖链下确定性哈希校验 |
| 链上数据量 | 大（快照/原文倾向） | 小（`traceCode + proofHash`） |
| 可用性 | 链节点异常易影响主流程 | 锚定失败不阻塞主流程 |
| 迁移能力 | 强绑定单一链平台 | Provider 策略可切换 |
| 前端呈现 | 常停留在“已上链”文案 | 展示 `txId`/摘要/状态并支持复验 |
| 工程审计 | 常缺少标准部署产物 | 合约、ABI、部署记录齐全 |

## 10. 业务与产品价值

对“橘源通”这类农业数字化小程序，区块链创新价值体现在：

1. 提升跨主体信任：渠道商、采购方可基于 `txId` 做外部核验。
2. 降低系统中断风险：链路异常不拖垮核心业务流程。
3. 控制实施成本：以最小锚定实现“可信增强”，而非重资产链改。
4. 支持逐步升级：先 MVP，后续可按业务需要逐步扩展。

## 11. 边界与约束（需明确对外口径）

当前方案边界：

- 区块链不替代病害识别、分级定价、风险打级等核心算法逻辑。
- `verified` 的主判定来自本地哈希一致性，不是“链上交易成功”本身。
- 仅做摘要存证，不承诺链上可直接还原业务明文数据。

该边界定义是本项目创新的一部分：把区块链用于“证据增强”，而不是“替代业务引擎”。

## 12. 后续可迭代方向

1. 多网络支持：在 EVM 基础上扩展主网/联盟链环境模板。
2. 异步锚定任务化：引入队列提升高峰期吞吐与重试能力。
3. 证据核验 API 标准化：提供面向外部合作方的只读核验接口。
4. 可信报告导出：按批次生成“链下快照 + 链上交易”合并证明文档。
5. 监控指标：新增锚定成功率、确认耗时、RPC 失败率等运营指标。

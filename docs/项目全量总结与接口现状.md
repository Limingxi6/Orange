# 橘源通项目全量总结与接口现状（统一版）

更新时间：2026-04-21

## 1. 项目全量概览

- 前端：微信小程序（`pages/` + `services/`）。
- 后端：NestJS + Prisma + MySQL + Redis + JWT。
- AI：Python（病害、果实分级、风险规则、LLM 任务封装）。
- 统一返回：`{ code, message, data }`。

## 2. 已落地能力

- 认证：登录、发码、资料、退出。
- 批次：列表、详情、创建、阶段更新。
- 农事日志：列表、创建、类型字典。
- 病害：识别（兼容双路由）、记录查询。
- 分级定价：AI 入口 + 规则入口 + 基准价 + 建议。
- 风险：摘要、评估、历史，含路径兼容。
- 产品/溯源：产品列表、二维码生成、溯源详情、溯源校验。
- 天气/上传：当前天气、预报、图片上传。

## 3. 当前接口现实口径（结论）

- 全局前缀：`/api`。
- 例外：`/ai/disease/predict`、`/ai/fruit/grade`。
- 风险兼容：`/api/risk/:batchId` 与 `/api/risk/assessment` 同时保留。
- 前端和后端已经从“旧 `/api/qrcode/generate`”收敛到 `/api/products/:id/qrcode`。

## 4. 仍需关注的不一致点

- Fruit 感知远程路径默认值与 Python 服务默认路由存在潜在错位（需在环境变量上强制对齐）。
- 部分历史文档仍混用 `batch_id` 与 `batchId`；代码层已做兼容，但文档需统一以 camelCase 为主、snake_case 为兼容。

## 5. 现在可直接用于联调的主接口

- `POST /ai/disease/predict`
- `POST /ai/fruit/grade`
- `GET /api/risk/:batchId`
- `GET /api/trace/:code`
- `GET /api/trace/:code/verify`

详单请以 [docs/api-interface-list.md](./api-interface-list.md) 为准。

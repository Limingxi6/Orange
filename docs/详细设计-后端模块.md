# 详细设计-后端模块

更新时间：2026-04-22

## 1. 模块总览

`backend/src/modules` 主要模块：

- `auth`
- `user`
- `batch`
- `log`
- `disease`
- `price`
- `risk`
- `product`
- `trace`
- `weather`
- `upload`
- `ai`

## 2. 模块职责与关键接口

### 2.1 auth

职责：登录、验证码、资料、退出。  
关键接口：`/api/auth/login`、`/api/auth/send-code`、`/api/auth/profile`、`/api/auth/logout`。

### 2.2 user

职责：用户信息查询与权限控制示例。  
关键接口：`/api/users/me`、`/api/users/:userId`。

### 2.3 batch

职责：批次生命周期管理。  
关键接口：`/api/batches`、`/api/batches/:id`、`/api/batches/:id/stage`。

### 2.4 log

职责：农事日志查询与写入，日志类型字典。  
关键接口：`/api/logs`、`/api/logs/types`。

### 2.5 disease

职责：病害识别编排、识别记录管理。  
关键接口：`/ai/disease/predict`、`/api/disease/predict`、`/api/disease/records`。

### 2.6 price

职责：分级与定价规则、AI 感知融合、建议输出。  
关键接口：`/ai/fruit/grade`、`/api/price/grade`、`/api/price/baseline`、`/api/price/suggestion`。

### 2.7 risk

职责：风险评估、摘要、历史记录。  
关键接口：`/api/risk/summary`、`/api/risk/assessment`、`/api/risk/:batchId`、`/api/risk/history`。

### 2.8 product

职责：产品列表与二维码生成。  
关键接口：`/api/products`、`/api/products/:id/qrcode`。

### 2.9 trace

职责：溯源详情与校验、proof/anchor 编排。  
关键接口：`/api/trace/:code`、`/api/trace/:code/verify`。

### 2.10 weather

职责：天气获取与缓存。  
关键接口：`/api/weather/current`、`/api/weather/forecast`。

### 2.11 upload

职责：图片上传。  
关键接口：`/api/upload/image`。

### 2.12 ai

职责：统一 AI 叙事编排，调用 `src/llm`。

## 3. 跨模块协作

- `disease` 依赖 `upload`、`ai`、`prisma`
- `price` 依赖 `ai`、远程感知客户端、规则引擎、`prisma`
- `risk` 依赖 `risk-engine`、`ai`、`prisma`
- `product` 与 `trace` 互相关联（二维码生成驱动 trace 记录）

## 4. 关键 DTO 兼容策略

- 病害：`batchId` 与 `batch_id` 同时支持
- 分级：`packageType` 与 `packaging` 同时支持
- 风险历史：`batchId` 与 `batch_id` 同时支持
- 分页：`limit` 与 `pageSize` 同时支持

## 5. 异常处理策略

- 参数或业务异常：抛 `BusinessException`。
- 数据不存在：统一 `NOT_FOUND` 错误码。
- 外部服务异常：记录告警并回退。

## 6. 代码维护建议

1. 新接口优先复用现有 module/service/dto。  
2. 配置新增必须同步三处。  
3. 不破坏前端稳定字段，必要时保留兼容字段。

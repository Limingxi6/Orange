## 2. 项目简介参考

### 2.1 项目一句话介绍

“橘源通”是一款面向柑橘种植与流通场景的农业数字化管理工具，提供批次管理、农事日志、病害识别、果实分级、价格评估、风险预警和二维码溯源等功能。

### 2.2 项目核心价值

可围绕以下角度展开：

- 帮助果园建立标准化批次档案
- 记录种植、施肥、用药、采收等关键农事信息
- 通过 AI 辅助识别病害，提升巡园效率
- 对果实品质进行分级和参考定价
- 提前发现种植或流通风险
- 通过二维码向消费者展示可信溯源信息
- 使用 AI 生成解释、建议、问答和宣传文案

### 2.3 使用场景

建议手册中写清楚以下典型场景：

1. 果园管理员新建一个柑橘批次
2. 农事人员每天记录施肥、灌溉、打药、采摘等操作
3. 巡园时发现叶片异常，拍照进行病害识别
4. 采收后上传果实信息，进行分级和价格评估
5. 管理员查看某批次风险预警
6. 系统生成溯源码，用于包装、销售或展示
7. 消费者扫码查看产地、批次、农事记录和品质信息

## 4. 各章节写作参考

## 1. 产品介绍

### 写作重点

说明“橘源通”不是单一识别工具，而是围绕柑橘生产、质检、定价和溯源的综合管理工具。

### 可参考内容

“橘源通”通过微信小程序提供轻量化使用入口，用户无需安装复杂软件，即可完成批次登记、农事记录、AI 识别、品质评估和溯源展示等操作。

主要功能包括：

- 批次管理：建立每一批柑橘的数字档案
- 农事日志：记录生产过程中的关键操作
- 病害识别：通过图片辅助判断病害类型
- 果实分级：根据颜色、大小、成熟度、缺陷等因素评估等级
- 价格评估：提供零售和批发价格参考
- 风险预警：提示批次可能存在的生产或质量风险
- 二维码溯源：让消费者扫码查看批次信息
- AI 辅助：生成解释、建议、问答和宣传文案

## 2. 登录与首页

### 写作重点

使用通俗语言说明用户从打开小程序到进入首页的流程。

### 应包含内容

- 如何打开微信小程序
- 是否需要授权登录
- 首页有哪些功能入口
- 登录失败或网络异常时的处理方式

### 示例写法

用户进入“橘源通”小程序后，可根据页面提示完成登录。登录成功后，系统将进入首页。首页通常展示批次管理、病害识别、果实分级、风险预警、溯源管理等功能入口。

如果登录失败，请检查网络连接，并确认微信授权状态是否正常。若多次尝试仍无法进入，可联系系统管理员处理。

## 3. 批次管理

### 写作重点

让用户理解“批次”是后续所有功能的基础。

### 建议说明

批次是系统中用于管理一组柑橘生产、采收、质检和溯源信息的基本单位。一个批次通常对应某一果园、某一品种、某一时间段或某一次采收。

### 新建批次应说明的字段

可根据实际页面调整：

- 批次名称
- 批次编号
- 果园或地块
- 柑橘品种
- 种植面积
- 采收时间
- 负责人
- 备注信息

### 操作步骤参考

```markdown
1. 进入小程序首页。
2. 点击“批次管理”。
3. 点击“新增批次”。
4. 按页面提示填写批次信息。
5. 确认信息无误后点击“保存”。
6. 保存成功后，可在批次列表中查看该批次。
```

### 注意事项

- 批次信息应尽量真实、完整。
- 批次编号建议保持唯一，便于后续追踪。
- 已用于溯源的批次，不建议随意修改核心信息。
- 后续农事日志、病害识别、风险预警和溯源信息通常都与批次关联。

## 4. 农事日志

### 写作重点

强调农事日志用于沉淀生产过程信息，也是风险评估和溯源展示的重要依据。

### 常见农事类型

- 施肥
- 灌溉
- 除草
- 修剪
- 病虫害防治
- 用药
- 采收
- 巡园
- 其他操作

### 新增日志操作步骤

```markdown
1. 进入“农事日志”页面。
2. 选择对应批次。
3. 点击“新增记录”。
4. 选择农事类型。
5. 填写操作时间、操作内容、负责人等信息。
6. 如有需要，可上传现场图片。
7. 点击“保存”。
```

### 记录建议

- 用药记录应尽量包含药剂名称、用量、使用时间和操作人。
- 采收记录应包含采收时间、数量、质量情况等信息。
- 异常情况应及时记录，例如病害、天气灾害、裂果、落果等。
- 农事记录越完整，后续溯源信息越可信。

## 5. 病害识别

### 写作重点

必须说明这是 AI 辅助识别，不应替代专业农技判断。

### 功能说明

病害识别功能支持用户上传或拍摄柑橘叶片、果实等图片，系统根据图像特征给出可能的病害类型、置信度、严重程度和处理建议。

### 结果字段说明

建议解释以下字段：

| 字段 | 含义 |
|---|---|
| 病害名称 | 系统识别出的可能病害类型 |
| 置信度 | 系统对识别结果的可信程度 |
| 严重程度 | 对病害影响程度的判断 |
| 处理建议 | 针对当前结果给出的参考措施 |
| 是否需要人工复核 | 当结果不确定时，提示用户进一步确认 |

### 操作步骤

```markdown
1. 进入“病害识别”页面。
2. 点击“拍照”或“上传图片”。
3. 选择清晰的叶片或果实图片。
4. 点击“开始识别”。
5. 等待系统返回识别结果。
6. 查看病害名称、置信度、严重程度和建议。
```

### 图片拍摄建议

- 尽量选择光线充足的环境。
- 保持图片清晰，避免严重模糊。
- 病斑区域应在画面中清楚可见。
- 避免同时拍摄过多杂乱背景。
- 可从不同角度拍摄多张图片辅助判断。

### 安全提示

病害识别结果仅作为辅助参考。若系统提示置信度较低、需要人工复核，或病害面积较大、发展较快，应联系农技人员进行现场判断。

## 6. 果实分级与价格评估

### 写作重点

说明分级和价格是根据规则、模型和输入信息生成的参考结果，不是最终交易价格。

### 功能说明

果实分级功能根据果实品种、颜色、大小、成熟度、缺陷比例等因素，对果实品质进行等级评估，并提供零售和批发价格参考。

### 结果字段说明

| 字段 | 含义 |
|---|---|
| 品种 | 当前评估的柑橘品种 |
| 等级 | 系统给出的果实等级 |
| 颜色评分 | 对果皮颜色表现的评分 |
| 缺陷比例 | 果面缺陷或瑕疵的估计比例 |
| 大小评分 | 对果实大小均匀度或规格的评分 |
| 成熟度评分 | 对成熟程度的评分 |
| 零售价格区间 | 面向零售场景的参考价格 |
| 批发价格区间 | 面向批发场景的参考价格 |
| 分级原因 | 系统给出该等级的主要依据 |
| 风险提示 | 与质量、销售或价格相关的风险说明 |
| 影响因素 | 影响本次评估结果的关键因素 |

### 操作步骤

```markdown
1. 进入“果实分级”页面。
2. 选择或填写果实品种。
3. 上传果实图片或填写相关品质信息。
4. 点击“开始评估”。
5. 查看等级、评分、价格区间和原因说明。
```

### 价格说明

手册中应明确：

- 系统价格为参考价格，不等同于最终成交价。
- 实际价格会受到市场供需、地区、季节、渠道、包装、运输等因素影响。
- 批发价和零售价适用场景不同，不应混用。
- 当果实存在明显缺陷或成熟度异常时，系统可能给出风险提示。

## 7. 风险预警

### 写作重点

说明风险预警用于提示用户关注异常，不是处罚或最终结论。

### 功能说明

风险预警功能根据批次信息、农事记录、病害识别结果、天气或规则条件，对批次当前状态进行风险评估，并给出风险等级、原因和建议。

### 风险等级示例

| 风险等级 | 含义 | 建议处理 |
|---|---|---|
| 低风险 | 当前未发现明显异常 | 保持正常管理 |
| 中风险 | 存在需要关注的问题 | 建议加强巡查和记录 |
| 高风险 | 存在较明显异常或潜在损失 | 建议尽快处理并人工复核 |

### 操作步骤

```markdown
1. 进入“风险预警”页面。
2. 选择需要查看的批次。
3. 查看风险等级、风险原因和处理建议。
4. 根据建议进行现场检查或补充记录。
```

### 注意事项

- 风险等级会随批次信息和农事记录变化。
- 缺少关键记录可能影响风险判断。
- 高风险结果应优先安排人工确认。
- 农业生产受天气、土壤、病虫害等多因素影响，系统建议应结合现场情况使用。

## 8. 二维码与溯源

### 写作重点

突出溯源面向消费者和销售展示，信息应真实可信。

### 功能说明

二维码溯源功能可以为批次生成专属二维码。消费者或采购商扫码后，可查看该批次的产地、品种、农事记录、质量信息、采收信息等内容。

### 操作步骤

```markdown
1. 进入“溯源管理”页面。
2. 选择需要生成溯源码的批次。
3. 点击“生成二维码”。
4. 保存或下载二维码。
5. 将二维码用于包装、标签、宣传物料或销售展示。
```

### 溯源页面建议展示内容

- 批次名称
- 产地信息
- 品种信息
- 采收时间
- 农事记录摘要
- 质量或分级信息
- 风险状态
- 企业或果园介绍
- 联系方式

### 注意事项

- 溯源内容应真实、准确。
- 不建议夸大品质、功效或产量。
- 已公开展示的信息应避免包含个人隐私或敏感数据。
- 修改批次信息后，应确认溯源页面是否同步更新。

## 9. AI 解释、建议与问答

### 写作重点

明确 AI 的边界：负责解释和辅助建议，不负责替代专业判断。

### 可写内容

系统中的 AI 功能主要用于辅助生成解释、建议、问答和文案。例如：

- 对病害识别结果进行通俗解释
- 对风险等级给出处理建议
- 对果实分级结果说明原因
- 生成面向消费者的溯源介绍文案
- 回答用户关于批次、品质或管理建议的问题

### 必须写清楚的限制

- AI 输出仅基于系统已有输入信息生成。
- AI 不应臆造未提供的数据。
- 农业诊断建议应保守使用。
- 对于低置信度、严重病害、大面积异常等情况，应联系专业农技人员。
- AI 不替代病害分类、价格计算和风险打级等核心规则或模型结果。

## 10. 常见问题参考

### Q1：为什么病害识别结果显示“需要人工复核”？

可能原因包括图片不清晰、病斑不明显、光线不足、背景复杂或模型置信度较低。建议重新拍摄清晰图片，必要时联系农技人员现场判断。

### Q2：果实分级结果可以直接作为销售定价吗？

不建议直接作为最终成交价。系统价格为参考价格，实际交易价格还会受到市场行情、采购渠道、包装规格、运输成本和供需关系影响。

### Q3：风险等级较高应该怎么办？

建议先查看系统给出的风险原因，再结合现场情况进行检查。若涉及病害、药剂使用、天气灾害或质量异常，应及时安排人工复核和处理。

### Q4：二维码生成后可以修改批次信息吗？

可以根据系统权限修改，但已用于销售或公开展示的溯源信息应谨慎调整，确保消费者扫码看到的信息真实一致。

### Q5：农事日志填错了怎么办？

如果系统支持编辑，可进入对应记录进行修改。如果已影响溯源展示或风险评估，应确认修改后的信息是否同步更新。

## 12. 写作风格要求

AI 写作工具生成手册时，应遵循以下风格：

- 使用简体中文
- 面向普通农业用户，避免过多技术术语
- 操作步骤清晰，优先使用编号列表
- 每个功能都说明“作用、入口、操作步骤、结果解释、注意事项”

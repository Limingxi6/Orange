# 橘源通项目现状（按仓库事实）

更新时间：2026-04-22

## 1. 当前完成度

- 前端：13 个页面已接入主流程（含创建批次、创建日志）。
- 后端：核心业务模块均已注册进 `AppModule`。
- AI：`ai/src` + `ai/service` 已具备训练脚本、推理逻辑和 HTTP 服务入口。
- LLM：已通过 `backend/src/llm` 统一接入。

## 2. 主链路状态

- 病害识别：可运行，支持兼容路由，支持结果落库。
- 果实分级：可运行，规则裁决 + 感知层回退，支持结果落库。
- 风险评估：可运行，规则引擎主导 + 文本润色。
- 溯源校验：可运行，支持 hash 校验，支持可选链锚定扩展。

## 3. 近期事实更新

1. Trace 模块支持锚定提供方策略（`hash/notary/evm`）。  
2. 环境变量体系已包含 trace 与 EVM 配置项。  
3. `.env.example`、`configuration.ts`、`env.validation.ts` 已保持 trace 相关一致。
4. 产品二维码支持“小程序码优先，失败回退普通二维码”，可用于微信扫一扫直达溯源页。
5. AI 建议能力已统一到 `backend/src/llm` 的四类建议任务（病害/分级/风险/溯源），并接入对应业务模块与页面展示。
6. 建议任务已具备统一回退与埋点（`taskType/promptVersion/model/latencyMs/success/fallback/errorCode`）。

## 4. 当前风险与待办

- Fruit 感知默认路径 `/ai/fruit/perception` 与 Python 默认路由需要明确对齐。
- 退出登录仍是 MVP 语义（未实现 token 黑名单）。
- 生产前需确保前端 mock 回退策略按环境关闭或受控。
- AI 建议文案质量仍需上线后按场景抽检，关注 fallback 比例与动作可执行性。

## 5. 建议下一步

1. 固化“开发/测试/生产”三套配置模板。  
2. 增加核心链路回归（接口契约 + fallback 分支）。  
3. 以周为单位输出质量指标：调用成功率、超时率、回退率。

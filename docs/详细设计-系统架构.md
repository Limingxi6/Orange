## 2. 后端运行时详细设计

### 2.1 启动与全局中间能力

启动文件：`backend/src/main.ts`。

启动步骤：

1. 创建 Nest 应用。  
2. 读取配置并绑定端口。  
3. 设置全局前缀 `/api`，排除 `/ai/disease/predict`、`/ai/fruit/grade`。  
4. 打开 CORS。  
5. 映射静态目录 `/uploads/`。  
6. 注册全局 `ValidationPipe`（`whitelist + forbidNonWhitelisted + transform`）。  
7. 开发环境注入 Swagger。  
8. 监听服务。

### 2.2 请求生命周期

1. 请求进入 `Controller`。  
2. DTO 校验与类型转换。  
3. JWT 守卫鉴权（`@Public` 例外）。  
4. 角色守卫/本人守卫。  
5. 进入 `Service` 执行业务逻辑。  
6. `TransformInterceptor` 包装统一响应。  
7. 如异常发生，`HttpExceptionFilter` 包装统一错误格式。

### 2.3 响应与错误结构

成功结构：

```json
{ "code": 0, "message": "ok", "data": {} }
```

错误结构：

```json
{ "code": 1002, "message": "参数错误", "data": null }
```

核心错误码：

1. `1001` 未授权。  
2. `1002` 参数错误。  
3. `1003` 数据不存在。  
4. `1004` 操作失败。  
5. `1005` 无权限。

## 3. 后端模块详细设计（逐模块）

## 3.1 `auth` 模块

### 接口清单

1. `POST /api/auth/login`  
2. `POST /api/auth/send-code`  
3. `GET /api/auth/profile`  
4. `POST /api/auth/logout`

### 3.1.1 登录处理细节

输入：`phone/password`。

处理步骤：

1. `AuthService.login` 按手机号查用户。  
2. 密码校验：
   1. bcrypt hash 直接 compare。  
   2. 历史 `salt$iterations$hash` 走 pbkdf2。  
3. 校验 `status === active`。  
4. 生成 JWT payload（`sub/phone/role/nickname`）。  
5. 返回 `token + userInfo`。

异常：

1. 用户不存在或密码错误。  
2. 用户状态禁用。

### 3.1.2 发码处理细节

1. 计算验证码长度与过期时间。  
2. 读缓存判断发送频率。  
3. 写 Redis（失败回退内存 Map）。  
4. 开发环境回传 `debugCode`。

### 3.1.3 profile 与 logout

1. `profile` 按当前 user id 查用户返回映射字段。  
2. `logout` 仅返回 `success:true`，前端清 token。

## 3.3 `batch` 模块

### 接口清单

1. `GET /api/batches`  
2. `GET /api/batches/:id`  
3. `POST /api/batches`  
4. `PUT /api/batches/:id/stage`

### 3.3.1 批次列表

1. 接收 `keyword/stage/page/limit/pageSize/sort`。  
2. `sort=latest/oldest` 转 Prisma `orderBy`。  
3. `keyword` 作用于 `batchNo/orchardName/variety` 模糊查询。  
4. 分页返回 `list + total`。

### 3.3.2 批次详情

1. 查询批次主信息。  
2. 读取 `_count.farmingLogs/_count.products`。  
3. 返回 `logsCount/productsCount`。

### 3.3.3 创建批次

1. 解析 `managerId`（默认当前用户）。  
2. 校验负责人存在且 `active`。  
3. 校验 `batchNo` 唯一（若用户传入）。  
4. 无 `batchNo` 时调用 `generateBatchNo`（最多重试 5 次）。  
5. 事务中创建：
   1. `batch` 记录。  
   2. 默认 `product` 记录。

设计意图：保证批次创建后“我的产品”可见。

### 3.3.4 阶段更新

1. 校验批次存在。  
2. 更新 `stage` 与时间戳。  
3. 返回 `success:true`。

## 3.5 `disease` 模块

### 接口清单

1. `POST /api/disease/predict`  
2. `POST /ai/disease/predict`（兼容）  
3. `GET /api/disease/records`

### 3.5.1 `/api/disease/predict` 详细流程

1. `FileInterceptor` 接收 `file`。  
2. 解析 `batchId`，若未传调用 `resolveBatchId` 用当前用户最近批次。  
3. 生成最终 `imageUrl`：
   1. 优先请求体 `imageUrl`。  
   2. 否则上传文件调用 `UploadService.uploadImage`。  
4. 调 `DiseaseInferenceClient.infer(imageUrl, batchId)`：
   1. 若配置可用走远程 HTTP。  
   2. 失败则 `inferWithLocalRule`。  
5. 计算 `needManualReview` 与 `status`。  
6. 调 `AiNarrativeService.explainDiseaseResult` 生成建议。  
7. 写入 `disease_records`（含 `rawResult`）。  
8. 返回扩展字段（`modelVersion/boxes/reasoning/severityText`）。

### 3.5.2 `/ai/disease/predict` 兼容流程

1. 接收 `batchId/batch_id`。  
2. 复用 `DiseaseService.predict`。  
3. 补充兼容字段：`label/advice/image_url`。  
4. 保证 `needManualReview` 默认逻辑可用。

### 3.5.3 记录查询

1. 支持 `batchId` 过滤。  
2. 支持分页参数 `page/pageSize`。  
3. 返回 `list/total/page/pageSize`。

## 3.6 `risk` 模块

### 接口清单

1. `GET /api/risk/summary`  
2. `GET /api/risk/assessment`  
3. `GET /api/risk/history`  
4. `GET /api/risk/:batchId`（兼容）

### 3.6.1 评估数据准备

`RiskService.assessAndStore` 聚合：

1. 批次阶段信息。  
2. 最新天气缓存（current + forecast）。  
3. 近 7 天病害记录（总数、高危数、最新置信度）。  
4. 最近灌溉日志时间。

### 3.6.2 规则计算（`RiskEngineService`）

规则项：

1. 病害扩散风险（未来3天降雨 + 生长关键阶段）。  
2. 干旱胁迫风险（高温 + 长时间无灌溉）。  
3. 病害历史风险（近 7 天病害频次与高危样本）。  
4. 无命中时给基础低风险项。

综合分级：

1. `overallScore >= 60 -> high`。  
2. `30 <= overallScore < 60 -> mid`。  
3. 其他为 `low`。

### 3.6.3 LLM 润色与落库

1. 构造规则 `reason/suggestion`。  
2. 调 `AiNarrativeService.polishRiskAssessment`。  
3. 落库 `risk_records`，`source_data` 保留规则命中明细。  
4. 输出兼容字段 `level/levelText/reason/suggestion`。

### 3.6.4 历史与摘要

1. `summary` 在无记录时会触发少量即时评估补数据。  
2. `history` 支持 `batchId/batch_id` 与分页兼容。

## 3.7 `price` 模块

### 接口清单

1. `POST /ai/fruit/grade`（兼容）  
2. `POST /api/price/grade`  
3. `GET /api/price/baseline`  
4. `GET /api/price/suggestion`

### 3.7.1 AI 分级编排（`PriceService.aiGrade`）

处理步骤：

1. 生成 `requestId`。  
2. 输入归一化：
   1. 渠道映射（电商/批发/摆摊/商超）。  
   2. 包装映射（简装/礼盒/精品礼盒）。  
   3. 数值裁剪（直径、糖度、重量）。  
3. 若有 `batchId`，校验批次存在并读取品种。  
4. 感知层：
   1. `FruitInferenceClient.inferPerception` 远程调用。  
   2. 失败时 `localPerceptionFallback`。  
5. 合并特征并进入规则引擎。  
6. 计算 `grade + retail/wholesale price range`。  
7. 生成默认 `reason/riskWarning`。  
8. 调 LLM 优化 reason。  
9. 尝试写 `fruit_grade_records`（失败只告警不阻断）。  
10. 返回完整结果。

### 3.7.2 规则分级接口 `/api/price/grade`

1. 可选批次校验。  
2. 调 `determineGrade` + `calculatePrice`。  
3. 返回规则结果。

### 3.7.3 基准价与建议接口

1. baseline 返回品种、地区、单位、等级基准映射。  
2. suggestion 支持按 `batchId` 推断 grade，或直接按参数计算。

### 3.7.4 评分与定价算法

质量分：

`qualityScore = color*0.3 + size*0.3 + maturity*0.25 + (1-defectRatio)*100*0.15`

等级规则：

1. A：质量分高 + 缺陷低 + 多指标门槛达标。  
2. B：中等门槛达标。  
3. C：其余。

定价：

`finalPrice = basePrice * channelCoeff * packageCoeff`

价格区间：

1. 零售：`final * [0.92, 1.08]`。  
2. 批发：`final * [0.62, 0.72]`。

### 接口清单

1. `GET /api/products`  
2. `POST /api/products/:id/qrcode`

### 3.8.1 产品列表

1. 先执行 `ensureDefaultProductsForBatches` 自动补默认产品。

### 3.8.2 生成二维码

1. 校验产品存在。  
2. 生成 traceCode（可覆盖）。

5. 更新产品 `qrCodeUrl`。  
6. 调 `TraceService.createOrUpdateForProduct` 保持 trace 与二维码一致。  
7. 返回 `qrcodeType/qrcodeFallback/qrcodeFallbackReason`。

## 3.9 `trace` 模块

### 接口清单

1. `GET /api/trace/:code`  
2. `GET /api/trace/:code/verify`

### 3.9.1 trace 记录生成策略

入口：`generateAndPersistTraceRecord(productId, traceCode)`。

步骤：

1. 聚合数据：product、batch、logs、disease。  
2. 构建三类快照：`batchSnapshot/logsSnapshot/inspectionsSnapshot`。  
3. 生成 proof：当前固定 hash proof。  
4. 写入或更新 `trace_records`。  
5. 若启用 EVM 锚定，异步增强写回锚定状态。

### 3.9.2 详情接口

1. 根据 traceCode 查询记录。  
2. 不存在时尝试从 code 推导 productId 自动生成。  
3. 聚合快照信息与 LLM 溯源文案。  
4. 返回 proof + anchor + 聚合数据。

### 3.9.3 校验接口

1. 读取 record 与快照。  
2. 重算 hash 与存储值比对。  
3. 识别历史占位 hash 时自动修复重建。  
4. 更新验真状态并返回。  
5. `verified` 判定仅由本地 hash 决定。

### 3.9.4 provider 设计

1. `HashProofProvider`：本地 hash 证明。  
2. `NotaryAnchorProvider`：HTTP notary 对接。  
3. `EvmAnchorProvider`：链上合约锚定。  
4. `TraceModule` 依据 `TRACE_ANCHOR_PROVIDER` 选择 anchor provider。

## 5. 页面详细设计（13 页）

## 5.1 登录页 `pages/login`

1. 输入手机号和验证码。  
2. 发码按钮触发 `authService.sendCode`。  
3. 登录按钮触发 `authService.login`。  
4. 登录成功后再拉 `getProfile`，确保本地用户信息一致。  
5. 跳转 `mine` 页。

## 5.2 首页 `pages/home`

1. 校验 token，无 token 跳 `mine`。  
2. 并发加载天气、风险摘要、最近批次。  
3. 快捷功能入口：病害识别、扫码溯源、果实分级、天气预警。  
4. 扫码后用 `traceService.extractTraceCode` 解析并跳溯源页。

## 5.3 批次列表 `pages/batch-list`

1. 拉批次列表。  
2. 支持关键词防抖搜索。  
3. 点击卡片进详情。  
4. 新建按钮进创建页。

## 5.4 批次详情 `pages/batch-detail`

1. 并发加载批次详情与日志。  
2. 展示最近 5 条日志。  
3. 支持阶段更新 ActionSheet。  
4. 支持跳病害识别、农事日志、风险页。

## 5.5 批次创建 `pages/batch-create`

1. 表单校验：名称、品种、地块、面积、日期。  
2. 调 `batchService.create`。  
3. 成功后返回上页并触发刷新。

## 5.6 日志列表 `pages/farming-log`

1. 解析批次 id（参数/全局/缓存）。  
2. 加载日志类型与日志列表。  
3. 支持按类型筛选。  
4. 支持查看日志详情弹层。  
5. 支持进入日志新增页。

## 5.7 日志创建 `pages/farming-log-create`

1. 初始化日志类型和批次列表。  
2. 选批次、选类型、输入描述、可上传图。  
3. 先上传图片，再创建日志。  
4. 成功后回跳日志页并刷新。

## 5.8 病害识别 `pages/disease-recognize`

1. 选择图片。  
2. 调 `diseaseService.predict`。  
3. 展示标签、置信度、严重等级、建议。  
4. 可一键保存为农事日志（`source=disease_recognize`）。

## 5.9 风险预警 `pages/risk-warning`

1. 拉当前位置天气。  
2. 拉 15 天预报并切分 7+8。  
3. 拉风险评估与风险历史。  
4. 用 ECharts 绘制风险趋势图。

## 5.10 果实分级 `pages/fruit-grade`

1. 可上传图，也可只填结构化参数。  
2. 选择渠道/包装/地区/缺陷等级。  
3. 调 `priceService.gradeAndPrice`。  
4. 展示评分卡与价格区间。  
5. 异步拉基准价。

## 5.11 产品二维码 `pages/product-qrcode`

1. 拉产品列表。  
2. 对单产品生成二维码。  
3. 支持预览、保存到相册、复制溯源码。  
4. 支持扫码进入溯源页。

## 5.12 溯源详情 `pages/trace-view`

1. 从页面参数/扫码结果解析 traceCode。  
2. 调 `traceService.getInfo` 获取详情。  
3. 组装批次、分级、流程、病害、验真信息。  
4. 手动触发 `verifyChain` 重新验真。  
5. 支持复制 proofHash/txId。

## 5.13 我的页 `pages/mine`

1. onShow 检测登录态。  
2. 加载 profile。  
3. 加载二维码工作台（产品预览）。  
4. 加载今日记录预览。  
5. 支持退出登录。

## 6. Python AI 服务详细设计

入口：`ai/service/app.py`（FastAPI）。

接口：

1. `GET /health`  
2. `POST /predict/disease`  
3. `POST /predict/fruit`  
4. `POST /predict/risk`  
5. 兼容：`/ai/disease/predict`、`/ai/fruit/grade`、`/ai/fruit/perception`

## 6.1 DiseasePredictor

1. 优先本地病害模型预测。  
2. LLM 仅生成 advice/reasoning。  
3. 本地模型异常时回退规则逻辑。  
4. 保持 `severity` 与 `needManualReview` 合同字段。

## 6.2 FruitPredictor

1. 本地规则输出分级与价格是主路径。  
2. 可选模型 `FRUIT_GRADE_MODEL_PATH` 参与分级。  
3. 外部视觉分析仅用于补充特征，不替代核心计算。  
4. source 字段标记是否用了 external vision/model。

## 6.3 RiskPredictor

1. `RiskAssessmentService` 本地规则决定等级。  
2. 外部 API 仅润色 reason/suggestion。  
3. 失败时保留本地结果并记录 fallback 原因。

## 9. 关键异常与回退分支清单

| 分支 | 触发条件 | 系统行为 |
|---|---|---|
| 病害远程推理失败 | HTTP 非 2xx/超时/结构非法 | 回退 `mockRecognizeDisease` |
| 果实远程感知失败 | AI 服务不可用/字段缺失 | 回退 `localPerceptionFallback` |
| LLM 失败 | 配置缺失/HTTP 失败/JSON 解析失败 | 返回 fallback 文案 |
| MinIO 未启用 | `UPLOAD_MODE=minio` 且占位实现 | 返回业务异常提示改用 local |
| 微信小程序码失败 | token 失效/接口异常 | 回退普通二维码 |
| 锚定失败 | RPC/Notary 异常 | `anchorStatus=failed`，不影响 `verified` |

## 10. 详细设计结论

1. 当前实现满足 MVP 的“可运行、可回退、可兼容”目标。
